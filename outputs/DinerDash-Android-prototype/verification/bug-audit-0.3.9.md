# Diner Dash 0.3.9 bug audit

The audit covered the service model, action queues, furniture routes, guest/Flo/chef rendering, touch input, shop, profiles and career checkpoints. Most listed fixes are in the signed 0.3.9 APK. The standing-face change was a regression, corrected in 0.3.10; its claim is retracted below. This remains a reconstruction; the tests establish the listed contracts, not complete Windows runtime parity. The requested music-reference comparison is paused and GameAudio.java is unchanged.

| Priority | Trigger and defect | Correction and evidence |
| --- | --- | --- |
| P1 | Opening the endless shop parsed `item_desc` as a numbered purchase and crashed. Exhausting upgrades with unused credit also hid Continue. | Only `item_1`–`item_3` are purchase controls; empty choices expose Continue. Installed actual button gestures cover stocked and exhausted shops. |
| P1 | Replaying shift 5-10 repeatedly added its score to the saved completed total. | Preserve the original pre-final resume checkpoint, while saving the final best score and submitting the completed total. A second final win cannot inflate it. |
| P1 | Endless coffee appeared before purchase; purchased coffee and podium used the wrong destinations. | Initial endless stations are absent. Purchases activate authored destinations `(14,3)` and `(1,11)` on all 15 variants. |
| P1 | Five absent `bonusGoal` values became 800, lower than the ordinary goal. | Recovered default is twice `minimumTip`: 2-2=8,000; 2-4=10,000; 2-6=12,000; 4-6=14,000; 5-6=20,000. Existing best scores are evaluated against those correct thresholds. |
| P2 | Cancel could create a typed profile or leave the title showing a different player. Duplicate names were accepted. | Cancel/Back discard pending input and reload the active profile. Names normalize whitespace, preserve display case and reject case-insensitive duplicates. |
| P2 | Boy/man/critic departures skipped their second frames; missing IDs displayed unrelated reading/drinking poses. | Each transition runs for its authored frame count × 750 ms. Missing terminal IDs preserve the last exit pose; missing mood IDs preserve the preceding pose. One-frame default/senior/business transitions retain their original 750 ms timing. |
| P2 | **Retracted:** the audit incorrectly treated rounded satisfaction as a defect. | Lingo `integer(float)` rounds. The floor change made six-heart arrivals use the worried face. 0.3.10 restores the original bands: pose 1 at mood 1, pose 2 at 2–4, pose 3 at 5–10. The earlier tests used incorrect expectations. |
| P2 | The dish cart always showed its empty image. | Successful visits advance `full_0/1/2`; the second visit starts the 1,500 ms reset. Tests cover a third drop before the old timer fires. |
| P2 | Chez Flo carried-food labels used diner anchors. | The tray uses `chezflos`; flag/number children use their authored `chez` selectors. |
| P2 | Releasing a cancelled two-finger gesture could enqueue a station action. | Ignore release until the next fresh gesture begins. |
| P2 | A foreground frame stall discarded elapsed time above 100 ms, slowing customer/cooking clocks. | Process all elapsed time in steps of at most 100 ms, stopping when paused or ended. The installed regression simulates 500 ms. |

## Verification

All six model suites pass **40,910 intent checks**, including **12,477 furniture routes** through all 50 career and 15 endless maps with purchased stations/tables. A valid order → dirty table → wheel queue continues with a free hand and starts cooking. No additional route clipping was reproduced. All 50 career schedules close in the zero-travel service bot; it reaches 43 goals, which does not certify real play difficulty.

Historical result: all six installed Android suites passed **797 checks**, including incorrect standing-face expectations. This result does not validate that mapping. The historical counts were: 80 animation/input, 58 save/menu, 226 guest, 233 sprite, 94 audio, 106 new regressions. Before the fixes, the new data test failed 50/65 checks and the initial complete installed bug test failed 39/101. Four isolated menu/save/profile cases failed their intended assertions; the shop additionally produced a parsing crash. The cart capture was recentered to include its entire sprite, and the 106-check regression suite was rerun successfully without production changes.

Ordinary emulator gestures completed 1-1, tapped Continue and started playable 1-2 without a fatal exception. Final departure, carried-food, full-cart and 1-2 captures were visually inspected. This is one short real shift playthrough plus synthetic installed fixtures, not 50 physical-device playthroughs.

The final APK has **1,960 unchanged original media members**, 62 uncompressed MP3s, 26 uncompressed derived music WAVs, unchanged original assets/resources, valid ZIP CRC and the existing signing certificate. Installed bytes match the packaged APK. Version code is 12; SHA-256 is `5ce7776cbe848dc37cd32e0d91559568995b4fe355df87e752339c59d111b114`.

Instrumentation fixtures restored their saves. The separate touch run advanced the isolated emulator's test save: its pre-touch `run-as` backup failed because this release APK is not debuggable. The invalid snapshot was detected and no guessed restore was made; a valid post-touch snapshot was captured afterward. No physical device or its saves were accessed.

## Remaining issues and boundaries

- Hidden overflow parties still use WAITING internally instead of the original NEW state. Their patience is suspended, but the podium can boost hidden parties. This needs a separate queue-admission correction.
- Timer multiplier ownership, quick-seating happiness, weighted A* route selection/ties, and the original state-dependent tutorial/closing sequence still have fidelity gaps. Full elapsed-time catch-up was cheap in the desktop model probe (one tutorial hour in about 16 ms), but Android performance for very long foreground stalls has not been measured.
- The reported disappearing queue marks with a free hand still lack a reproduced failed destination. Successful mixed actions pass. The original clears pending actions after an invalid service action; that rule remains intact.
- Embedded font conversion, restaurant construction scenes, Goddess transformation and the ending sequence remain unfinished. The opening comic is present.
- No Windows runtime comparison or physical Android test ran. Audio sequencing/reference comparison remains paused; existing audio regression checks passed.
